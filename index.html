REST API + JSON: API Katalog Produk

Endpoint, method, status code · contoh PHP + simulator interaktif
Cerita Pembuka

Katalog produk UMKM ingin tampil di website, aplikasi mobile, dan marketplace sekaligus. Jika setiap tampilan mengambil data dengan cara sendiri, datanya cepat tidak sinkron. Solusinya: satu pintu data berupa API yang bisa dipakai semua klien.

Setelah pertemuan ini, saya bisa…

  • Menjelaskan apa itu REST API dan mengapa dipakai[cite: 9].
  • Merancang endpoint dan memilih method HTTP yang tepat[cite: 9].
  • Membaca dan menulis format JSON[cite: 9].
  • Memilih status code yang sesuai untuk setiap hasil[cite: 9].
  • Membuat API katalog produk sederhana dengan PHP + MySQL[cite: 9].
Analogi: API seperti pelayan restoran. Klien (pelanggan) tidak masuk ke dapur (database); ia memesan lewat pelayan dengan format yang disepakati, lalu pelayan membawa hasilnya[cite: 9].

1. Apa itu REST dan JSON?

REST adalah gaya perancangan API di atas HTTP: setiap data dianggap sebagai resource yang punya alamat (URL), dan aksi ditentukan oleh method HTTP. Server bersifat stateless: setiap request membawa semua informasi yang dibutuhkan[cite: 9].

JSON (JavaScript Object Notation) adalah format pertukaran data berbasis teks yang ringan dan mudah dibaca manusia maupun mesin[cite: 9].

{
  "id": 3,
  "name": "Keripik Pisang Gorontalo",
  "price": 25000,
  "category": "Makanan",
  "in_stock": true,
  "tags": ["camilan", "oleh-oleh"]
}

Aturan penting JSON: kunci wajib di dalam tanda kutip ganda, tidak boleh ada koma di akhir, dan tipe data yang dikenal: string, number, boolean, null, array, object[cite: 9].

Hindari: /getProduct, /deleteProduct?id=3. Pakai: GET /products/3, DELETE /products/3[cite: 9].

4. API Katalog Produk dengan PHP

Gunakan koneksi.php (PDO) dari Pertemuan CRUD, lalu buat satu file api/products.php yang membaca method dan mengembalikan JSON[cite: 9].

<?php
// api/products.php
require "../koneksi.php";
header("Content-Type: application/json; charset=utf-8");

function kirim($data, $kode = 200) {
    http_response_code($kode);
    echo json_encode($data, JSON_UNESCAPED_UNICODE);
    exit;
}

$method = $_SERVER['REQUEST_METHOD'];
$id     = isset($_GET['id']) ? (int) $_GET['id'] : null;
$body   = json_decode(file_get_contents("php://input"), true);

GET — daftar & detail

if ($method === 'GET') {
    if ($id) {
        $s = $pdo->prepare("SELECT * FROM products WHERE id = ?");
        $s->execute([$id]);
        $p = $s->fetch();
        $p ? kirim($p) : kirim(["error" => "Produk tidak ditemukan"], 404);
    }
    $rows = $pdo->query("SELECT * FROM products ORDER BY id DESC")->fetchAll();
    kirim(["data" => $rows]);
}

POST — tambah produk

if ($method === 'POST') {
    $name  = trim($body['name'] ?? '');
    $price = $body['price'] ?? null;
    if ($body === null) kirim(["error" => "JSON tidak valid"], 400);
    if ($name === '' || !is_numeric($price) || $price < 0)
        kirim(["error" => "Nama/harga tidak valid"], 422);

    $s = $pdo->prepare("INSERT INTO products (name, price, category_id) VALUES (?,?,?)");
    $s->execute([$name, $price, $body['category_id'] ?? 1]);
    kirim(["id" => $pdo->lastInsertId(), "name" => $name], 201);
}

PUT & DELETE

if ($method === 'PUT' && $id) {
    $s = $pdo->prepare("UPDATE products SET name=?, price=? WHERE id=?");
    $s->execute([$body['name'], $body['price'], $id]);
    $s->rowCount() ? kirim(["message" => "Diperbarui"]) : kirim(["error" => "Tidak ditemukan"], 404);
}
if ($method === 'DELETE' && $id) {
    $s = $pdo->prepare("DELETE FROM products WHERE id=?");
    $s->execute([$id]);
    http_response_code($s->rowCount() ? 204 : 404);
    exit;
}
kirim(["error" => "Method tidak didukung"], 405);

Memanggil dari JavaScript

const res = await fetch("/api/products.php");
const json = await res.json();
if (res.ok) tampilkan(json.data);
else alert(json.error);

Cek Pemahaman

Mengapa endpoint memakai kata benda, bukan kata kerja?

Karena aksi sudah ditentukan oleh method HTTP. DELETE /products/3 sudah jelas artinya, tidak perlu /deleteProduct[cite: 9].

Apa beda 400, 404, dan 422?

400: request rusak (misal JSON tidak valid). 404: resource tidak ada. 422: format benar tetapi isi gagal validasi (misal harga negatif)[cite: 9].

Mengapa POST yang berhasil memakai 201, bukan 200?

201 menegaskan bahwa resource baru telah dibuat, sehingga klien dapat mengetahui hasilnya lebih tepat[cite: 9].

Apa arti stateless pada REST?

Server tidak menyimpan konteks klien antar request; setiap request memuat semua informasi yang dibutuhkan (mis. token autentikasi)[cite: 9].
